Évaluer un risque
La matrice probabilité × impact
On donne à chaque menace une probabilité (va-t-elle se produire ?) et un impact (quelle gravité si elle se produit ?). La case
obtenue donne le niveau de risque.

===== PAGE 10 =====
La modélisation des menaces
Modéliser les menaces
En anglais : Threat modeling
Définition
Démarche structurée qui consiste à décrire un système, puis à chercher méthodiquement ce qui
peut mal tourner à chaque endroit, à l'aide d'une grille de questions.
Deux outils de description
DFD (diagramme de flux de données) : schéma des
utilisateurs, processus, bases de données et flux
Frontière de confiance : limite où les données changent de
zone (ex. Internet   réseau interne)
À retenir
Les attaques se produisent surtout au passage des frontières
de confiance : c'est là qu'on cherche en priorité.

===== PAGE 15 =====
Le vocabulaire
Les mots de l'IA utilisés dans le projet
Terme
Définition simple
Grand modèle de langage (LLM)
IA entraînée sur de grandes quantités de texte, capable de comprendre et de produire du texte.
Prompt (consigne)
Instructions écrites données au LLM : son rôle, sa tâche, le format attendu.
Agent IA
Programme qui utilise un LLM pour atteindre un objectif : il planifie, agit par étapes et utilise des
outils.
Outil
Fonction que l'agent peut appeler : lire un fichier, interroger une base de vulnérabilités, faire un
calcul.
Orchestrateur
Agent « chef d'orchestre » qui distribue le travail et fait circuler les résultats.
RAG
Technique qui fournit au LLM des documents de référence pour qu'il s'appuie sur des sources fiables.
Humain dans la boucle
Une personne valide les résultats importants avant leur utilisation.

===== PAGE 16 =====
Un choix d'architecture
Pourquoi plusieurs agents plutôt qu'un seul ?
Spécialisation
Chaque agent a une seule tâche et
une consigne courte : il se trompe
moins qu'un agent qui fait tout.
Contrôle
Chaque résultat intermédiaire est 
visible et vérifiable : on sait quel
agent a produit quelle erreur.
Moindre privilège
Chaque agent n'a accès qu'aux
outils dont il a besoin : un agent
compromis fait moins de dégâts.
À retenir C'est le même principe que la séparation des tâches dans une organisation : on découpe pour mieux contrôler.

===== PAGE 22 =====
Le format des échanges
Des résultats structurés, faciles à vérifier
{ 
  "id": "R-07", 
  "actif": "Console d'administration", 
  "menace": "Vol d'identifiants par hameçonnage", 
  "categorie": "STRIDE-S", 
  "probabilite": "moyenne", 
  "impact": "élevé", 
  "niveau": "élevé", 
  "traitement": "réduire", 
  "mesures": ["MFA FIDO2", "sensibilisation"], 
  "sources": ["STRIDE", "OWASP ASVS V2"], 
  "valide_par": null 
}
Pourquoi un format structuré ?
Chaque agent lit exactement ce que le précédent a
produit. On peut vérifier automatiquement que rien
ne manque.
Le champ « sources »
Chaque risque doit citer ses sources : c'est la première
parade contre les hallucinations.
Le champ « valide_par »
Il reste vide tant qu'un humain n'a pas validé le risque.
